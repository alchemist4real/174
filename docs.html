DOKUMENTASI PANDUAN UMUM

1. Pengantar MR-CAPSULES

📖 ISTILAH PENTING (buat yang masih awam):
  • Open-source = kode dan pengelolaannya terbuka, siapa saja boleh ikut berkontribusi
  • CBT pool = kumpulan soal pilihan ganda yang bisa dipakai berulang untuk latihan/ujian
  • HTML = format file dasar halaman web; semua materi/soal di platform ini disimpan sebagai file .html

MR-CAPSULES adalah platform edukasi open-source yang didedikasikan untuk melestarikan dan mendistribusikan sumber belajar mahasiswa kedokteran/kesehatan secara terpusat. Platform ini mengubah materi kuliah, praktikum, dan soal tahun lalu menjadi basis data HTML pilihan ganda yang interaktif (CBT pool).

2. Pengenalan Admin Panel

📖 ISTILAH PENTING (buat yang masih awam):
  • CBT = Computer Based Test, ujian teori lewat komputer (bukan kertas)
  • Kanban Board = papan tugas dengan kolom-kolom (Open → In Progress → Done) supaya progres kerja gampang dipantau
  • MCP = "jembatan" yang memungkinkan AI seperti Claude terhubung langsung ke Admin Panel dan menjalankan tugas otomatis
  • HTML = format file dasar halaman web; semua materi/soal di platform ini disimpan dalam bentuk file .html
  • Live Preview = fitur untuk langsung melihat tampilan file HTML tanpa perlu upload dulu

Seluruh kontributor akan bekerja menggunakan Admin Panel yang memiliki 4 fitur utama:

  • Dashboard: Melacak analitik aplikasi (Uptime, Total Pengguna, Member Online), log aktivitas hybrid, serta melihat papan peringkat kontributor (Leaderboard).
  • Files (File Manager): Mengelola struktur folder dan file HTML secara langsung. Terdapat HTML Editor berbasis CodeMirror bawaan dengan fitur live preview untuk mengecek materi.
  • Team (Organization): Manajemen anggota divisi, filter pengguna (Admin, Banned, Online), serta fitur Broadcast pengumuman dan pengaturan global (Maintenance / Sign-up).
  • Tasks (Task Board): Papan manajemen proyek dengan sistem Kanban (Open, In Progress, Developed, In Review, Done) dan tampilan Silabus. Penugasan dapat dibagi berdasarkan semester dan kategori materi (CBT, OSCE, Video, Summary).

3. Pembagian Divisi Kontributor

Kontribusi dalam MR-CAPSULES dibagi menjadi beberapa divisi utama. Anda dapat mendaftar tanpa rasa ragu, karena sistem ini didesain agar mudah dipelajari oleh siapa saja.

PENTING: Tidak perlu pengalaman (baik itu coding, IT, maupun organisasi) untuk masuk ke divisi mana pun! Workflow kerja teknis akan diberikan lebih lanjut setelah Anda bergabung.

A. Division Management (Pengurus)

Bertugas memastikan kelancaran alur kerja dari Task Board hingga publikasi. Melakukan assign tugas di Kanban Board, mengelola pengguna di tab Team, serta menyiarkan pengumuman.

B. Division Development (Pembuat Konten)

Bertugas meracik materi mentah menjadi file HTML/CBT yang interaktif. Mengambil tugas di Task Board, mengerjakannya, lalu memindahkannya ke kolom Developed (Wait for Review).

Catatan Teknis: KITA TIDAK MELAKUKAN CODING ASLI / MANUAL.

Pembuatan dan perbaikan kode seluruhnya menggunakan Viebo Code (istilah untuk men-generate kode menggunakan AI seperti Claude atau Antigravity). Peran developer lebih sebagai Prompt Engineer: menyuruh AI membuatkan soal dengan template yang sudah ada, lalu memasukkannya ke HTML Editor di tab Files.

C. Division Review & QA (Koreksi)

Memastikan setiap materi yang masuk kolom In Review di Task Board terbebas dari kesalahan ketik (typo) atau konsep yang keliru.

Mereka membedah live preview di HTML Editor, mencocokkan kunci jawaban dengan referensi asli. Jika lolos, tugas digeser ke Done. Jika salah, dikembalikan ke kolom In Progress agar Developer memperbaikinya via AI kembali.

MCP & API GATEWAY GUIDE

1. Integrasi MCP & API Gateway (AI Assistant Integration)

📖 ISTILAH PENTING (buat yang masih awam):
  • MCP (Model Context Protocol) = standar yang memungkinkan AI Assistant (Claude, dll) terhubung ke aplikasi lain. Cara pakainya BUKAN seperti coding atau "manggil fungsi" — Anda cukup chat/ngobrol biasa dengan Claude, lalu Claude sendiri yang otomatis menjalankan aksinya di belakang layar (mengambil task, upload file, dsb). Sama persis seperti Anda minta tolong asisten manusia, hanya saja asistennya AI yang langsung bisa "menyentuh" data di MR-CAPSULES.
  • API Gateway = pintu masuk yang mengatur lalu lintas permintaan dari luar (misalnya dari AI) ke sistem MR-CAPSULES
  • API Key = kunci rahasia berbentuk teks untuk membuktikan identitas saat AI/aplikasi luar mengakses server
  • OAuth 2.0 = metode login aman tanpa perlu membagikan password langsung ke aplikasi pihak ketiga
  • Connector = fitur di Claude.ai untuk menyambungkan Claude ke layanan luar, termasuk MR-CAPSULES
💬 INTINYA: MCP = NGOBROL, BUKAN CODING
Yang perlu Anda lakukan hanyalah mengetik permintaan dalam bahasa biasa ke chat Claude, misalnya: "Buatkan task baru untuk materi Fisiologi Saraf blok 1.3" atau "Cek file apa saja yang ada di folder blok 2.5". Claude yang akan menerjemahkan permintaan itu menjadi aksi teknis (memanggil tool tasks_create, content_list, dsb) secara otomatis di balik layar. Anda tidak perlu menghafal nama tool atau menulis kode apapun.

MR-CAPSULES menyediakan API Gateway & Model Context Protocol (MCP) serverless endpoint berbasis Streamable HTTP (MCP 2025-06-18). Fitur ini memungkinkan AI Assistant seperti Claude.ai Web, Claude Desktop, atau AI Agent eksternal untuk mengakses konten dan melakukan tugas secara otomatis di Admin Panel.

A. Cara Mengoperasikan & Mengisi API Key

  1. Buka Admin Panel dan pastikan Anda sudah terhubung ke salah satu Divisi (Management, Development, atau Review).
  2. Pilih tab API Keys di navigasi utama.
  3. Masukkan nama kunci pada bidang Key Name (contoh: Claude Web MCP) serta tentukan masa berlaku (Expires In).
  4. Klik tombol + Generate Key. Kunci rahasia berawalan mrc_... akan ditampilkan dalam kotak kuning.
  5. Klik tombol Copy dan simpan kunci tersebut segera karena tidak dapat ditampilkan kembali demi alasan keamanan.

B. Menghubungkan ke Claude.ai Web (Custom Connector)

Integrasi MCP MR-CAPSULES mendukung OAuth 2.0 PKCE Auto-Discovery (RFC 8414 & RFC 7591) resmi.

  1. Buka Claude.ai → Settings → Connectors → Klik Add Custom Connector (BETA).
  2. Name: Isi dengan mr capsules (atau nama pilihan Anda).
  3. URL: Isi dengan https://mr-capsules.vercel.app/api/mcp
  4. Advanced settings: BIARKAN KOSONG / JANGAN DIISI (Otorisasi OAuth 2.0 PKCE bekerja secara otomatis lewat Auto-Discovery).
  5. Klik Add → Klik Connect → Anda akan diarahkan ke halaman Login Mr. Capsules. Log in menggunakan akun Anda dan otorisasi selesai!
CATATAN: Penggunaan API Key dibatasi maksimum 5 kunci aktif per pengguna dengan batasan rate limit 60 request/menit untuk mencegah penyalahgunaan.

2. Referensi Lengkap MCP Tools & Hak Akses

Bagian ini merinci seluruh 70 method/tools yang tersedia lewat MCP Gateway, dikelompokkan berdasarkan fungsinya, beserta siapa saja yang berwenang menggunakannya.

PENTING: Meskipun sebuah tool "tampak" di daftar AI Assistant Anda, eksekusinya tetap divalidasi ulang oleh server berdasarkan role akun yang terhubung. Jika Anda tidak memiliki hak akses, permintaan akan ditolak (403/permission error) walau tool sempat dipanggil.

A. Level Akses (Role Hierarchy)

  • SuperAdmin: Pemegang kendali penuh sistem & codebase. Satu-satunya yang dapat mengedit file codebase backend/frontend, mengangkat/menurunkan Admin, dan menghapus akun secara permanen.
  • Admin: Diangkat oleh SuperAdmin. Mengelola konfigurasi sistem, konten, dan moderasi pengguna, namun tidak bisa mengubah hak Admin lain.
  • Reviewer: Anggota Divisi Review & QA. Berwenang atas siklus review tugas (start review, approve, reject, lapor isu).
  • Developer: Anggota Divisi Development. Berwenang mengambil (claim) dan mengumpulkan (submit) tugas.
  • Semua Pengguna Terautentikasi: Akses baca umum serta pengelolaan data milik sendiri (API key, kontribusi, WhatsApp, dsb).

PANDUAN DIVISION MANAGEMENT

1. Mengidentifikasi Konten yang Dibutuhkan per Blok

📖 ISTILAH PENTING (buat yang masih awam):
  • Gap konten = materi yang seharusnya ada di silabus tapi belum tersedia file HTML-nya di platform
  • Silabus = daftar resmi kuliah/praktikum dari program studi untuk satu blok
  • Template Lecture = format file HTML berisi rangkuman materi kuliah + kuis (lihat detail lengkap di tab Division Development)
  • Template CBT / Quiz Engine = format file HTML khusus soal ujian murni tanpa rangkuman materi, dengan mode Study/Exam/Drill (lihat detail lengkap di tab Division Development)
  • Task duplikat = dua task berbeda yang ternyata membahas topik yang sama, sehingga membuang waktu Developer

Tugas pertama Management adalah memetakan gap antara materi yang sudah ada di platform dan materi yang seharusnya ada. Ini dilakukan sebelum task apapun dibuat.

A. Langkah Audit Konten

  1. Buka tab Files di Admin Panel → navigasi ke folder blok yang ingin diaudit (contoh: content/semester 2/2.5/).
  2. Bandingkan file yang ada dengan silabus blok (daftar kuliah/praktikum resmi dari prodi). Catat materi yang belum punya file HTML.
  3. Cek tab Tasks di Kanban Board — pastikan materi yang belum ada belum punya task aktif (Open / In Progress / In Review) agar tidak duplikat assignment.

B. Jenis Konten HTML yang Dibutuhkan

Semua konten di MR-CAPSULES berbentuk file .html interaktif. Sesuai penjelasan lengkap di tab Division Development, ada dua jenis template yang dipakai, tergantung sumber materinya:

Fitur / Karakteristik Template HTML Lecture Template HTML CBT
Dipakai untuk task Materi kuliah teori & modul praktikum yang belum pernah dirangkum Naskah soal ujian CBT tahun lalu / bank soal siap pakai
Sumber Utama PPT Kuliah / Modul Praktikum Naskah Soal CBT Tahun Lalu / Bank Soal
Elemen Utama Tab 📋 Materi (Rangkuman) + Tab 🎯 Quiz Pure Engine Kuis (Study, Exam, Drill Mode)
Penyajian Materi Sub-tabs, Note boxes, Data tables, Diagram SVG Tidak ada (hanya lewat penjelasan di kuis)
CATATAN UNTUK MANAGEMENT: Saat membuat task (lihat Section 2), tentukan dulu sumbernya termasuk materi kuliah/praktikum baru (→ Template Lecture) atau naskah soal ujian siap pakai (→ Template CBT). Ini membantu Developer langsung tahu template mana yang harus dipakai tanpa perlu bertanya ulang.

C. Aturan Prioritas Sumber: PPT Lecture vs. Modul Praktikum

Jika untuk satu topik yang sama tersedia dua sumber (PPT lecture dan modul praktikum), ikuti hierarki berikut:

ATURAN EMAS: Pilih satu sumber yang paling lengkap — jangan buat dua file HTML terpisah untuk materi yang identik. Tujuannya menghindari duplikasi konten yang membingungkan pengguna.
KondisiSumber yang DipakaiAlasan
PPT Lecture & Modul Praktikum membahas topik identik, kedalaman berbeda Pilih yang lebih lengkap (biasanya modul praktikum — mencakup prosedur + teori) Modul praktikum umumnya sudah merangkum teori dari PPT plus penerapan klinis

Konten benar-benar sama persis (PPT = ringkasan modul) Pakai modul praktikum, abaikan PPT Hindari duplikasi; modul lebih terstruktur untuk dijadikan materi + soal

D. Cara Mengecek Kelengkapan via Files

  1. Di tab Files, buka folder blok target.
  2. Klik kanan (atau ikon titik tiga) pada file HTML yang ada → pilih Edit Code → gunakan Live Preview untuk melihat konten file tersebut secara cepat.
  3. Jika file HTML yang ada sudah mencakup materi dari PPT dan modul secara memadai, tidak perlu task baru. Jika belum lengkap, catat untuk di-update dengan membuat task revisi baru.

  3. Jika file HTML yang ada sudah mencakup materi dari PPT dan modul secara memadai, tidak perlu task baru. Jika belum lengkap, catat untuk di-update dengan membuat task revisi baru.

2. Menginput Task ke Task Board

Setelah audit selesai dan daftar gap konten tersusun, langkah berikutnya adalah membuat task di Kanban Board. Ada dua cara: manual via Admin Panel, atau otomatis via MCP (Claude.ai / Antigravity).

A. Cara Manual (via Admin Panel)

  1. Buka tab Tasks di Admin Panel.
  2. Klik tombol + Create Task (tombol ini hanya muncul untuk akun Management/Admin).
  3. Isi form dengan ketentuan berikut:
    • Title: Nama materi spesifik, jelas, dan konsisten. Format yang direkomendasikan: [Mata Kuliah] [Topik] — [Tipe]
      Contoh: Fisiologi Saraf Otonom — CBT atau Histologi Epitel — Identifikasi
    • Semester: Pilih semester yang sesuai (contoh: semester 2).
    • Block: Isi nomor blok (contoh: 2.5). Wajib diisi agar task muncul di tampilan Silabus.
    • Category: Isi sesuai peruntukan ujian: CBT untuk soal teori, atau nama blok/kategori custom (misal SOE 2.5, Praktikum Fisio). Field ini bebas diisi — gunakan nama yang konsisten agar mudah difilter di Kanban Board.
    • Priority: Sesuaikan urgensi:
      • urgent — ujian < 2 minggu lagi
      • high — ujian 2–4 minggu
      • normal — standar
      • low — cadangan / tidak mendesak
    • Description: Cantumkan detail sumber materi, misalnya: “Buat soal CBT dari PPT K10 am-i-counseling. Fokus pada prinsip dasar konseling dan hambatan komunikasi. Target ~20 soal.”
    • Target Path (opsional): Jika sudah tahu path file tujuan, isi di sini (contoh: content/semester 2/2.5/2.5 CBT_K10 am-i-counseling.html). Ini memudahkan Developer tahu di mana menyimpan hasil kerjanya.
    • Assign To (opsional): Pilih Developer tertentu dari dropdown jika ingin mendelegasikan secara langsung. Kosongkan jika ingin open claim.
  4. Klik Confirm. Task akan muncul di kolom Open pada Kanban Board.
TIPS: Dari tab Files, kamu bisa klik kanan file yang sudah ada → Create Task untuk pre-fill otomatis Target Path dan langsung membuka form task. Jauh lebih cepat daripada input manual satu per satu.

3. Memastikan Developer & Reviewer Tidak Redundan

Redundansi terjadi ketika satu anggota mengerjakan sekaligus mereview konten miliknya sendiri, atau ketika dua Developer membuat file untuk topik yang sama. Ini harus dicegah secara sistematis.

A. Prinsip Pemisahan Peran

  • Developer hanya boleh mengerjakan (claim) dan mengumpulkan (submit) task. Mereka tidak boleh mereview hasil kerja mereka sendiri.
  • Reviewer hanya boleh mereview task yang bukan miliknya. Jika seorang anggota merangkap Developer & Reviewer, Management harus memastikan ia tidak ditempatkan pada tugas yang sama.
  • Management (Admin/SuperAdmin) boleh memantau semua alur, namun sebaiknya tidak terlibat langsung dalam produksi konten agar bisa bertindak netral saat eskalasi.

B. Langkah Pencegahan Redundansi Developer

  1. Sebelum membuat task: Cek di Kanban Board (kolom Open, In Progress) apakah topik sudah ada task-nya. Gunakan filter atau search di tab Tasks.
  2. Saat assign task: Jika meng-assign langsung via form (bukan open claim), pastikan tidak ada dua task dengan topik identik di-assign ke Developer yang sama.
  3. Jika dua Developer mengklaim topik yang sama secara tidak sengaja: Management gunakan tasks_delete pada task duplikat, atau tambahkan note via tasks_add_note untuk mengarahkan Developer yang kedua ke topik lain.
  4. Pantau kolom Developed (Wait for Review): Jika ada dua file masuk untuk topik yang sama, Management menentukan mana yang lebih lengkap, lalu reject yang lebih lemah dengan catatan (melalui Reviewer).

C. Langkah Pencegahan Redundansi Reviewer

  1. Saat task masuk kolom In Review, Reviewer yang meng-klaim tidak boleh sama dengan Developer yang mengerjakan task tersebut. Cek nama di log task (tasks_logs) sebelum memulai review.
  2. Jika tim kecil dan tidak ada Reviewer lain yang tersedia, eskalasi ke Management — Management yang melakukan review sementara, atau tunda task hingga Reviewer tersedia.
  3. Gunakan field Note (tasks_add_note) untuk mendokumentasikan siapa yang sudah mereview sesi mana, terutama pada materi besar yang direview bertahap.

D. Monitoring via Kanban Board & Leaderboard

SinyalApa yang Harus Dilakukan Management
Satu Developer dominasi kolom In Progress (>5 task sekaligus) Batasi claim — tambahkan note di task agar Developer fokus menyelesaikan yang ada dulu
Tidak ada aktivitas di kolom In Review >3 hari Ping Reviewer via Broadcast (tab Team) atau tambahkan note urgency
Task di kolom Open sudah lama tidak diklaim Assign langsung ke Developer via form edit task, atau naikkan priority ke urgent
Satu anggota top Leaderboard tapi seluruh task belum Done Cek apakah ada task yang stagnan di In Review — review pipeline mungkin macet

E. Checklist Harian Management

  • Buka Kanban Board → pastikan tidak ada task yang stuck lebih dari 48 jam di satu kolom.
  • Cek Dashboard → Activity Log untuk mendeteksi aksi tak wajar (misal: submit tanpa claim, atau approve oleh Developer).
  • Review kolom Done mingguan → pastikan file HTML-nya benar-benar ada di tab Files (path sesuai).
  • Bandingkan jumlah task Done vs task Open untuk ukuran produktivitas divisi secara keseluruhan.

2. Memahami 2 Jenis Template HTML & Perbedaannya

Di MR-CAPSULES (khususnya standar Blok 2.5 FK), terdapat dua jenis template HTML utama. Sangat penting bagi Developer untuk memilih template yang tepat sesuai jenis task yang diklaim.

A. Template HTML Lecture (Materi & Quiz)

Template ini digunakan saat membuat file dari PPT Lecture atau Modul Praktikum. Contoh file acuan: 2.5 LECTURE_K10 am-i-counseling.html.

  • Struktur 2 Tab Utama: Terdiri dari tab 📋 Materi dan tab 🎯 Quiz di bagian atas.
  • Bagian Materi (Interaktif):
    • Materi dipecah menjadi beberapa Sub-Tabs per bab/topik.
    • Memiliki elemen Note Box berwarna (gold, blue, green, red, purp, teal) untuk poin-poin penting.
    • Memiliki Data Tables (dtable-wrap) untuk klasifikasi, dosis, atau kriteria diagnostik.
    • Mendukung diagram/flowchart SVG interaktif (misalnya alur komunikasi atau skema patofisiologi).
  • Bagian Quiz: Menyediakan kuis interaktif dengan pilihan ganda dan pembahasan langsung di tempat untuk menguji pemahaman materi kuliah tersebut.
  • Desain & Tipografi: Menggunakan variabel CSS modern dengan kombinasi font Google Fonts: Syne (Header), DM Sans (Body), dan DM Mono (Code/Data).

B. Template HTML CBT / Soal Ujian (Pure Quiz Engine)

Template ini digunakan khusus saat memasukkan Naskah Soal Ujian Tahun Lalu atau bank soal ujian murni. Contoh file acuan: 2.5 CBT_21 REECHARD GANTENG.html.

  • Tanpa Tab Materi: Berisi 100% engine kuis tanpa penyajian rangkuman kuliah di depannya.
  • 3 Mode Belajar Utama:
    • Study Mode: Menampilkan kunci dan pembahasan komprehensif segera setelah memilih opsi.
    • Exam Mode: Simulasi ujian terwaktu, jawaban tersembunyi hingga kumpul ujian, dilengkapi modal konfirmasi.
    • Drill Mode: Mode pengulangan tanpa skor — pengguna harus memilih opsi yang benar untuk maju.
  • Fitur Ujian Lengkap: Question Map (peta nomor), penanda soal (flag ⚑), statistik & riwayat skor lokal (localStorage), serta analisis akurasi per topik.
  • Struktur Data JS: Soal disimpan dalam array JavaScript utuh di bagian bawah file:
    const QUESTIONS = [{n:1, t:"Topik", q:"Pertanyaan...", o:["A","B","C","D","E"], a:"Kunci Jawaban", exp:"Pembahasan...", src:"Sumber"}, ...];
  • Desain & Tipografi: Menggunakan gaya retro-minimalist yang bersih dengan font Georgia untuk judul dan Courier New untuk elemen data.

3. Panduan Prompting AI & Formulasi Resmi (Dengan Breakdown)

Agar hasil generate kode AI konsisten dan langsung sesuai dengan standar MR-CAPSULES, gunakan formulasi prompt resmi berikut saat melakukan Vibe Coding.

A. Prompt untuk PPT Lecture / Modul Praktikum (Template Lecture)

Gunakan prompt ini ketika Anda mengunggah file Template HTML Lecture dan file PPT/Modul Materi ke AI.

Formulasi Prompt Resmi (Copy & Paste ke AI):

Pahami seluruh struktur, CSS, dan skrip JavaScript dari file template HTML Lecture yang saya berikan.

Tugasmu adalah membuat file HTML lengkap baru berdasarkan materi kuliah/modul yang saya unggah ini, dengan ketentuan berikut:

1. PEMAHAMAN SLIDE/MATERI UTUH:
   Pahami seluruh isi slide/modul dari awal sampai akhir. JANGAN SAMPAI ADA ILUSTRASI, TABEL, DIAGRAM, ATAU MATERI PENTING YANG KELEWAT. Jika ada diagram alur atau hubungan konsep di PPT, sajikan dalam bentuk diagram SVG/Mermaid atau tabel CSS yang rapi di dalam tab Materi.

2. SAJIKAN SESUAI TEMPLATE:
   - Bagi materi ke dalam sub-tabs yang logis (misal: Overview, Patofisiologi, Diagnosis, Tata Laksana, Referensi).
   - Gunakan komponen note box (gold, blue, green, red, purp, teal) untuk menyoroti poin kunci, definisi, atau peringatan klinis.
   - Buat POOL SOAL QUIZ YANG BANYAK di tab Quiz (minimal 15-20 soal pilihan ganda) yang mencakup seluruh poin materi kuliah tersebut, lengkap dengan pembahasannya.

3. JUDUL DAN AKSEN WARNA KUSTOM:
   - Berikan judul yang sesuai dan menarik di bagian header (contoh: "Am I Counseling? — Quiz Keterampilan Dasar Konseling").
   - Pilih aksen warna khas di variabel CSS :root (--teal, --blue, --purp, atau --red) yang cocok dengan tema materi medis ini.

Keluarkan seluruh kode HTML utuh dalam satu block code tanpa ada bagian yang dipotong (no placeholders/TODO).

B. Prompt untuk Soal CBT Tahun Kemarin (Template CBT)

Gunakan prompt ini ketika Anda mengunggah file Template HTML CBT dan naskah/dokumen Soal Ujian CBT Tahun Lalu ke AI.

Formulasi Prompt Resmi (Copy & Paste ke AI):

Pahami seluruh engine kuis, struktur CSS, dan array JavaScript `QUESTIONS` dari file template HTML CBT yang saya berikan.

Tugasmu adalah menyajikan seluruh naskah soal ujian ini ke dalam template HTML CBT tersebut, dengan ketentuan berikut:

1. PRESERVASI KELENGKAPAN SOAL:
   Sajikan TEPAT [masukkan jumlah soal, misal: 105] SOAL dari naskah ini ke dalam array `QUESTIONS`. JANGAN SAMPAI ADA SATU PUN SOAL, OPSI JAWABAN, ATAU NOMOR YANG TERLEWAT ATAU DIPOTONG.

2. FORMULASI ARRAY QUESTIONS:
   Setiap objek soal harus memiliki struktur:
   - `n`: Nomor urut soal (1, 2, 3, dst.)
   - `t`: Nama topik/sub-materi singkat (misal: "Fisiologi Saraf", "Farmakologi", "Gizi Daur Hidup")
   - `q`: Teks pertanyaan lengkap (sertakan kasus/vignette jika ada)
   - `o`: Array 5 pilihan jawaban `["A", "B", "C", "D", "E"]`
   - `a`: Teks string kunci jawaban yang BENAR (harus persis sama dengan salah satu opsi di `o`)
   - `exp`: Pembahasan lengkap dan rinci mengapa jawaban tersebut benar dan mengapa opsi lain kurang tepat, berdasarkan teori medis di PPT/Modul.
   - `src`: Referensi slide/PPT (contoh: "PPT Merokok dan Alkoholisme — dr. Yudhi")

3. JUDUL DAN AKSEN WARNA:
   - Sesuaikan bagian `.logo-wordmark` dan `.logo-tag` di header (contoh: "21 PILL SAPI", Blok "2.5").
   - Atur warna aksen visual yang sesuai di CSS :root.

Keluarkan seluruh kode HTML utuh tanpa potongan agar siap saya simpan langsung ke file .html.

Rule 2: Preservasi Presisi Soal Menyebutkan jumlah pasti soal (misal 105 soal) agar AI tidak berhenti di tengah jalan atau sengaja memotong soal dengan komentar /* soal 10-100 disingkat */.
